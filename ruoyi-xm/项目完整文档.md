# 微信团购商城 — 完整项目文档

> 基于 RuoYi-Vue 3.8.9、Spring Boot、MyBatis 和原生微信小程序整合的本地生活团购商城系统。
> 最后更新：2026-06-02

---

## 一、项目概述

### 1.1 系统定位

这是一个面向本地生活、到店团购、门店核销、商家经营和平台运营的 SaaS 系统。

核心参与方：

- 消费者：浏览商家与团购商品、下单、支付、到店核销、查看订单
- 商家/店员：登录商家端、处理订单、扫码核销、管理商品和门店、查看财务
- 平台运营：审核商家、监管订单、处理售后、查看财务与数据分析

### 1.2 当前代码结构

当前仓库已经从“双小程序目录”整理为“单小程序前端目录”：

| 层 | 当前目录 | 说明 |
|----|----------|------|
| 小程序前端 | `wx_app/` | 同时承载 C 端页面与商家端页面 |
| 商家端页面 | `wx_app/pages/merchant/*` | 商家端页面入口 |
| 商家端接口封装 | `wx_app/api/merchant-mini/*` | 商家端 API 模块 |
| 运营后台 | `ruoyi-vue-wxmini-main/ruoyi-ui/` | 平台运营后台 |
| 后端服务 | `ruoyi-vue-wxmini-main/` | 所有 API、数据库访问和微信能力 |

说明：

- 原 `merchant_app/` 目录已废弃并移除
- 业务上仍保留“C 端”和“商家端”两套路由、两套登录态和两套接口边界
- 文档中再出现 `merchant_app`，默认视为历史目录名

### 1.4 四端协作关系

```text
消费者
  -> wx_app/pages/*
  -> /wxmini/**

商家/店员
  -> wx_app/pages/merchant/*
  -> /wxmini/merchant-mini/**

平台运营
  -> ruoyi-ui
  -> /mall/**, /system/**

后端服务
  -> ruoyi-admin + ruoyi-mall-* + ruoyi-wxmini
```

### 1.5 多商家模型

系统仍按多商家 SaaS 模式设计：

- 平台管理多个商家
- 商家管理自己的门店、员工、商品、订单和财务
- C 端数据需按商家和小程序上下文隔离
- 商家端数据需按商家与门店权限隔离

数据库和接口设计必须围绕这些归属字段：

- `merchantId`
- `storeId`
- `userId`
- `staffId`

### 3.3 金额约定

所有金额字段以**分**（整数）存储。前端展示时除以 100 转为元。示例：`19800` → `¥198.00`。

### 3.4 商品与团购关系

团购不是商家主表上的固定开关，而是商品的营销归属。

| 表/字段 | 规则 |
|------|------|
| `groupon_activity` | 按商家创建团购促销活动 |
| `product.groupon_id` | 可为空；为空表示普通商品，不为空表示团购商品 |
| `product.merchant_id` | 必须与关联的 `groupon_activity.merchant_id` 一致 |

查询规则：

- 普通商品：`product.groupon_id IS NULL`
- 团购商品：`product.groupon_id IS NOT NULL`
- C 端团购列表只返回已上架商品、进行中的活动、且未过期的数据。
- 商家没有团购时，不需要特殊字段；查询结果为空即可。

新增分销商表：

建议字段：

| 字段 | 说明 |
|------|------|

商家表需要增加：


```text
distributor_id
```

适用表：

- `mall_order`
- `order_item`
- `groupon_activity`
- `groupon_activity_item`
- `merchant_settlement_record`

- `distributor_id` 应从 `merchant.distributor_id` 推导。
- 不允许前端随意传入其他分销商 ID。
- 分销商查询必须强制过滤 `distributor_id = 当前分销商 ID`。
- 商家查询必须强制过滤 `merchant_id = 当前商家 ID`。

### 4.5 C 端订单状态机

```
                ┌─────────────┐
                │ PENDING_PAY │  用户下单后
                │   (待支付)    │
                └──────┬──────┘
           ┌───────────┼───────────┐
           ▼           ▼           ▼
     ┌──────────┐ ┌───────────┐ ┌──────────┐
     │CANCELLED │ │PAID_UNUSED│ │ REFUNDING│
     │  (已取消) │ │  (待使用)  │ │  (退款中) │
     └──────────┘ └─────┬─────┘ └─────┬────┘
                        ▼             ▼
                  ┌───────────┐ ┌──────────┐
                  │  USED_    │ │ REFUNDED │
                  │ COMPLETED │ │  (已退款) │
                  │  (已完成)  │ └──────────┘
                  └───────────┘
                        │
                  ┌──────────┐
                  │  CLOSED  │  超时未支付自动关闭
                  │  (已关闭) │
                  └──────────┘
```

| 状态值 | 前端展示 | 可执行操作 |
|--------|---------|-----------|
| `PENDING_PAY` | 待支付 | 去支付、取消订单 |
| `PAID_UNUSED` | 待使用 | 查看核销码、申请退款 |
| `USED_COMPLETED` | 已完成 | 再来一单、评价订单 |
| `REFUNDING` | 退款中 | 查看进度 |
| `REFUNDED` | 已退款 | 重新购买 |
| `CANCELLED` | 已取消 | 重新购买 |
| `CLOSED` | 已关闭 | 重新购买 |

### 4.7 支付流程

```
    ↓
```

### 5.6 扫码核销端到端流程

```
C 端用户                    商家端                      后端
   │                         │                          │
   │ 支付成功 → 订单状态      │                          │
   │ PAID_UNUSED              │                          │
   │ 系统生成 writeOffCode    │                          │
   │ = "LY8012"              │                          │
   │                         │                          │
   │ Canvas 生成二维码 ───────→│                          │
   │ 二维码内容 = "LY8012"    │                          │
   │                         │                          │
   │ 到店出示二维码           │                          │
   │ ────────────────────────→│ wx.scanCode()            │
   │                         │ 读取结果 = "LY8012"       │
   │                         │                          │
   │                         │ POST /write-off/LY8012 ──→│
   │                         │                          │ 校验订单状态
   │                         │                          │ 校验有效期
   │                         │                          │ 更新为 COMPLETED
   │                         │                          │
   │                         │←──── { success: true } ──│
   │                         │ toast "核销成功"           │
   │                         │                          │
   │←── C 端下次刷新订单 ─────│                          │
   │     状态变为 COMPLETED   │                          │
```

**后端核销校验清单**:

| 校验项 | 失败原因 |
|--------|---------|
| 核销码对应订单是否存在 | "未找到对应订单" |
| 订单状态是否为 `PENDING_VERIFY` | "该订单已核销完成" / "当前订单状态不可核销" |
| 团购券是否在有效期内 | "团购券已过有效期" |

### 5.7 商家端响应解析差异

商家端的响应解析与 C 端不同：

| 对比项 | C 端 (wx_app) | 商家端 (merchant_app) |
|--------|---------------|----------------------|
| API 前缀 | `/wxmini/` | `/wxmini/merchant-mini/` |
| Token 格式 | 原始 token（无 Bearer） | `Bearer {token}` |
| Token 存储 key | `token` | `merchantToken` |
| 响应解析 | 取整个 `{code, msg, data}` | 直接取 `data` 字段 |
| 订单状态 | PENDING_PAY → PAID_UNUSED → USED_COMPLETED | PENDING_ACCEPT → ... → COMPLETED |

## 七、端到端业务流程

### 7.1 消费者购买流程

```
进入小程序 → 浏览首页 → 搜索/分类 → 查看商家详情
    → 查看商品详情 → 加入购物车/立即购买
    → 确认订单(选择数量/优惠券) → 提交订单
    → 微信支付 → 支付成功 → 查看订单(核销码+二维码)
    → 到店出示二维码 → 商家扫码核销 → 订单完成
    → 评价订单
```

### 7.2 商家运营流程

```
商家登录 → 查看工作台(待接单/待核销/销售额)
    → 订单管理: 接单 → 发货 → 确认送达
    → 核销管理: 扫码/手动核销团购券
    → 商品管理: 上架/下架/编辑商品
    → 门店设置: 修改门店信息
    → 员工管理: 添加/编辑/分配权限
    → 财务: 查看收入/申请提现
```

### 7.3 平台运营流程

```
运营登录后台 → 审核商家入驻申请
    → 管理商家列表/商家等级
    → 查看订单/处理异常/售后
    → 财务管理: 平台收益/商家分账/提现审批
    → 数据分析: 销售排行/订单统计
```

### 7.4 分销商运营流程

```
超级管理员登录后台
    → 分销商管理: 新增/编辑/禁用/重置密码
    → 切换为某个分销商
    → 查看该分销商名下商家、订单、团购、结算
    → 退出分销商视角，返回超级管理员

分销商登录后台
    → 查看自己名下商家
    → 管理自己名下商家的商品、团购、订单、结算
    → 不能查看其他分销商和其他分销商下的商家
```
