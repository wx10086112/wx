### P0-1: JWT 签名验证被注释，token 可被任意伪造

**证据文件**：`ruoyi-vue-wxmini-main/ruoyi-mall-common/src/main/java/com/ruoyi/mall/common/service/impl/WxMiniJwtServiceImpl.java`

**证据① — 默认密钥为 "asd"（第 44 行）**：
```java
// jwt密钥
@Value("${token.secret:asd}")    // ← 未配置时默认 "asd"，3个字符可暴力破解
private String key;
```

**证据② — 签名验证被注释（第 74-77 行）**：
```java
public Boolean verifyToken(String token) {
    JWT jwt = JWTUtil.parseToken(token);
    jwt.setKey(key.getBytes());
    // 校验有效期和签名
    //        return jwt.verify();    // ← 被注释掉了！不做签名校验
    return jwt.validate(0);            // ← 只检查有效期，不验证签名
}
```

**危害**：拿到任意一个未过期 JWT，篡改 payload 中的 `userId` 后仍通过验证，可假冒任意用户。

**修复要求**：
1. 恢复 `jwt.verify()` + `jwt.validate(0)` 同时检查
2. 删除默认值 `:asd`，改为 `${token.secret}` 强制配置
3. 增加 `@PostConstruct` 启动时校验密钥长度 ≥ 32 位
4. 配置文件中添加 `token.secret` 生产环境随机密钥

**验收标准**：篡改 JWT payload → 返回 401；未配置 token.secret → 启动报错

### P0-6: 金额计算 Long 整数除法截断

**证据文件**：`ruoyi-vue-wxmini-main/ruoyi-wxmini/src/main/java/com/ruoyi/wxmini/service/impl/MerchantMiniServiceImpl.java`

**证据 — 第 80-81 行费率常量 + 第 535-537 行计算逻辑**：
```java
    private static final int MERCHANT_RATE = 90;     // 第 80 行
    private static final int PLATFORM_RATE = 10;     // 第 81 行

    // 第 535-537 行：
    Long payAmount = order.getPayAmount() != null ? order.getPayAmount().longValue() : 0L;
    Long merchantAmt = payAmount * MERCHANT_RATE / 100;   // 整数除法截断！
    Long platformFee = payAmount * PLATFORM_RATE / 100;   // 整数除法截断！
```

**危害**：`199分 * 90 / 100 = 179分`（Java Long 整数除法），实际应为 `179.1分`。每笔交易丢失 `0.1分`，累计导致商户和平台对账不平。

**同样问题在 MockService 也存在**（`MerchantMiniMockServiceImpl.java:934-935`）：
```java
    dto.setMerchantAmount(orderDto.getPayAmount() * MERCHANT_RATE / 100);
    dto.setPlatformFeeAmount(orderDto.getPayAmount() * PLATFORM_RATE / 100);
```

**修复要求**：
1. 使用 `BigDecimal` 进行金额运算，`RoundingMode.HALF_UP`
2. 统一实体和数据库金额单位

**验收标准**：199 分金额 × 90% = 179.1 分，不能截断为 179 分

### P0-7: 金额单位三方不一致（数据库/Java代码/文档互相矛盾）

**证据① — 数据库 `01_create_tables.sql` 用 DECIMAL（元）**：
```sql
`balance` DECIMAL(12,2) DEFAULT 0.00 COMMENT '账户余额',
`total_amount` DECIMAL(10,2) NOT NULL DEFAULT 0.00 COMMENT '订单总金额',
`pay_amount` DECIMAL(10,2) DEFAULT 0.00 COMMENT '实付金额',
```

**证据② — `10_groupon_activity_item.sql` 用 BIGINT（分）**：
```sql
`original_price`  BIGINT NOT NULL DEFAULT 0 COMMENT '原价，单位分',
`groupon_price`   BIGINT NOT NULL DEFAULT 0 COMMENT '团购价/现价，单位分',
```

**证据③ — Java `MallOrder.java` 用 BigDecimal（元）**：
```java
private BigDecimal totalAmount;    // ← 元
private BigDecimal payAmount;      // ← 元
```

**证据④ — 文档 §3.3 写"分"**：
> "所有金额字段以**分**（整数）存储。示例：19800 → ¥198.00"

**证据⑤ — Java 代码当作 Long（分）运算**（同上 P0-6）：
```java
Long payAmount = order.getPayAmount().longValue();  // BigDecimal → Long（丢失精度）
Long merchantAmt = payAmount * 90 / 100;             // 当作分运算
```

**危害**：跨表 JOIN 计算时，DECIMAL（元）× BIGINT（分）差 100 倍。Java 代码有时当元（BigDecimal），有时当分（Long 运算）。**这是系统性的金额灾难**。

**修复要求**（二选一）：
- **方案A**：数据库统一为 `BIGINT`（分），Java 统一为 `Long`（分），前端 ÷100 显示
- **方案B**：数据库统一为 `DECIMAL`（元），Java 统一为 `BigDecimal`（元），废除所有 Long 运算

推荐方案 A（分单位），符合阿里巴巴 Java 开发手册规范，避免浮点数精度问题。

**验收标准**：任意金额字段的存储/读取/计算使用同一单位，无 100 倍误差

## 🕐 2026-05-26 第三轮：分销商权限与数据隔离问题

**关键链路**：
```

  → SysLoginService 调 UserDetailsServiceImpl
    → userService.selectUserByUserName(username)
      → MyBatis 查 sys_user 表
        → 表里没有 account_type / distributor_id / merchant_id 列 ❌
          → SysUser.java 的 accountType 默认 "PLATFORM"
          → distributorId = null
            → SecurityUtils.getAccountType() = "PLATFORM"
            → SecurityUtils.getDistributorId() = null
              → MallMerchantController.list() 不过滤 distributorId
              → MallDistributorController 权限校验失败或返回空数据
```

**涉及文件**：
- `sql/ry_20250417.sql` — `sys_user` 建表语句缺 3 列
- `ruoyi-common/.../entity/SysUser.java` — 已有字段 ✅ （但 DB 没列，MyBatis 映射不到）
- `ruoyi-framework/.../service/UserDetailsServiceImpl.java` — 已从 SysUser 取这些字段 ✅
- `ruoyi-common/.../utils/SecurityUtils.java` — 已有 getAccountType / getDistributorId ✅

**修复要求**：
1. `ry_20250417.sql` 的 `sys_user` 表增加：
```sql
`account_type`    VARCHAR(32)  DEFAULT 'PLATFORM' COMMENT '账号类型（PLATFORM/DISTRIBUTOR/MERCHANT）',
`distributor_id`  BIGINT       DEFAULT NULL       COMMENT '绑定分销商ID',
`merchant_id`     BIGINT       DEFAULT NULL       COMMENT '绑定商家ID',
```
2. 已运行的数据库需要手动 ALTER TABLE 加这 3 列
3. 给测试用的分销商账号（`sys_user` 中）设置 `account_type = 'DISTRIBUTOR'` 和对应的 `distributor_id`
