### 3.3 分页方案

直接使用 RuoYi 内置的 PageHelper（已在 `application.yml` 配置），Controller 层用 `startPage()` + `getDataTable()` 即可。

### 3.4 返回格式

统一使用 RuoYi 的 `AjaxResult` + `TableDataInfo`：

```java
// 列表分页
@TableDataInfo  // 注解自动包装
public TableDataInfo list(Merchant query) {
    startPage();
    List<Merchant> list = merchantService.selectList(query);
    return getDataTable(list);
}

// 单条/操作
public AjaxResult detail(Long id) {
    return AjaxResult.success(merchantService.selectById(id));
}
```

### 3.5 登录认证改造

**管理后台**: 直接复用 RuoYi 已有的 `SysLoginController` + JWT 机制，不需要改动。

**商家小程序**: 改造 `MerchantMiniController.login()`：
- `merchant_user` 表存储账号密码（BCrypt 加密）
- 登录时查库验证，生成 JWT token
- token 中携带 `merchantId`、`staffId`、`roleKey`
- 其他接口通过 `WxMiniUserContext` 获取当前商家ID，实现数据隔离

## 六、关键设计决策

### 6.1 为什么所有代码放在 ruoyi-wxmini 而不新建模块？

- 项目已有 `ruoyi-wxmini` 作为业务模块，商家小程序代码已在此处
- 新建模块需要修改根 pom.xml 和多个依赖配置，增加复杂度
- 管理后台的 Controller 放在 `controller/merchant/` 子包下即可区分

### 6.2 Domain 实体用 Lombok 还是手写 getter/setter？

- 项目已引入 Lombok（DTO 全部用 `@Data`）
- Domain 实体统一用 `@Data` + `@TableName` 注解
- 保持与 RuoYi 系统实体风格一致

### 6.3 分页查询统一返回 TableDataInfo

- 前端 `real.js` 期望的返回格式: `{ code: 200, rows: [...], total: N }`
- RuoYi 的 `TableDataInfo` 正好匹配此格式
- 非分页接口返回 `AjaxResult.success(data)`

### 6.4 商家小程序的数据隔离

- 每个接口通过 `WxMiniUserContext.getMerchantId()` 获取当前商家ID
- 所有 Mapper 查询必带 `WHERE merchant_id = ?`
- 不需要额外的数据权限框架，简单可靠

### 6.5 前端切换策略

- 每个模块 `real.js` 已定义好所有函数和 URL
- 切换时只需修改 `index.js` 中的 import 来源或直接将 `real.js` 内容合并到 `index.js`
- **建议按阶段切换，一个模块一个模块来，便于测试回滚**

## 七、测试要点

### 7.1 管理后台核心流程

1. 商家列表 → 搜索/分页 → 点击详情 → 修改抽成比例 → 保存
2. 商品列表 → 按商家筛选 → 新增商品 → 上架/下架 → 删除
3. 全部订单 → 按状态筛选 → 查看详情(含商品明细)
4. 售后订单 → 处理退款
5. 平台流水 → 商家分账 → 提现记录 → 审批提现
6. Dashboard → 统计数据正确 → 图表渲染正常

### 7.2 商家小程序核心流程

1. 登录 → 选择角色 → 获取 token → 进入工作台
2. 工作台 → 统计数字正确 → 待处理订单列表
3. 订单列表 → 按状态筛选 → 查看详情
4. 核销 → 输入核销码 → 验证成功/失败
5. 商品管理 → 新增/编辑/上下架
6. 财务概览 → 收入统计 → 发起提现
