## 2026-05-26 微信支付特约商户三方分账全链路

### 状态

```text
两条独立链路已全部接通，退款API和用户端退款仍待补 (截至2026-05-28)
```

> 微信支付链路从单一直连商户改造为「特约商户 + 商家 + 分销商」三方分账架构。本章节明确区分两条独立的业务链路：**用户支付链路**（用户发起，秒级完成）和 **T+1 自动打款链路**（系统定时触发，次日到账）。两者通过订单核销事件衔接，但动作主体、触发时机、涉及接口完全不同。

---

### 链路一：用户支付链路

> **触发时机**: 用户在小程序点击"立即支付"
> **动作主体**: 用户 → 微信 → 后端回调
> **耗时**: 秒级（用户授权支付）
> **涉及资金**: 用户 → 微信 → 平台商户号（全额）

```
用户点击支付
    │
    ▼
WxPayController.createPay()
    │  校验订单归属 + 待支付状态
    │  stub模式: 创建PaymentRecord → 返回模拟参数
    │  真实模式: AbsWxPayBaseService.createOrder()
    │           → buildOrderParam() [按商家AppID构建]
    │           → wxPayService.createOrderV3(JSAPI)
    │           → saveOrderInfo() [创建PaymentRecord]
    │           → 返回 prepay_id + 签名参数
    │
    ▼
用户确认支付（微信客户端）
    │
    ▼
微信异步回调 POST /wxmini/pay/notify
    │  WxPayNotifyController.payNotify()
    │  → parseOrderNotifyV3Result()
    │  → MallOrder.status=PAID, payTime
    │  → PaymentRecord: transactionId + payStatus=PAID + payTime  ✅
    │
    ▼
用户核销（扫码/手动核销）
    │  WriteOffServiceImpl.writeOff()
    │  → publishEvent(OrderCompletedEvent) ──→ 触发链路二
    │
    ▼
退款（管理员审批）
    │  handleRefund() → RefundRecord.status=2
    │  → publishEvent(RefundApprovedEvent) ──→ 触发链路二逆向
    │  → [wxPayService.refundV3() 待接入]
    │  → [refundNotify 回调 → RefundRecord.status=4]
```

| 环节 | 核心类 | 完成度 | 说明 |
|------|--------|--------|------|
| 支付发起(stub) | WxPayController.createPay() | ✅ | 创建PaymentRecord + 返回模拟参数 |
| 支付发起(真实) | AbsWxPayBaseService.createOrder() | ✅ | V3 JSAPI + saveOrderInfo写入PaymentRecord |

### 链路二：T+1 自动打款链路

> **触发时机**: 订单核销完成（事件驱动）+ 定时任务自动打款
> **动作主体**: 系统（@Async 事件 + @Scheduled 定时）
> **耗时**: 核销后即时生成记录，次日10:00自动打款
> **涉及资金**: 平台商户号 → 商家零钱 / 分销商零钱

```
核销完成 → OrderCompletedEvent
              │
              ▼
SettlementEventListener.onOrderCompleted() [@Async]
    │
    ├─→ 1. profitLedgerService.createLedger()
    │      OrderProfitLedger: 无分销商 90/10, 有分销商 85/10/5
    │
    ├─→ 2. platformIncomeService.createIncome()  ✅
    │      PlatformIncome: 记录平台佣金收入
    │
    ├─→ 3. settlementService.createSettlementForOrder()
    │      MerchantSettlementRecord: status=WAITING_T1
    │      预计打款时间 = 明天 10:00
    │
    └─→ 4. distributorSettlementService.createSettlementForOrder() [有分销商]
           DistributorSettlementRecord: status=WAITING_SETTLEMENT

=== T+1 定时任务触发（次日10:00后，每5分钟扫描）===

SettlementTransferTask.processWaitingTransfer() [@Scheduled]
    │  → settlementService.selectWaitingTransfer(50)
    │  → 对每条 WAITING_T1 记录:
    │     platformTransferService.createMerchantTransfer(id, "system-auto")
    │       → 校验状态 + receiverOpenid
    │       → 幂等检查
    │       → 创建 PlatformTransferRecord
    │       → stub模式: 直接标记 ARRIVED
    │       → 真实模式: wxPayService.getMerchantTransferService().createTransfer()
    │                 → PlatformTransferRecord(TRANSFERRING)
    │
    ▼
微信转账回调 POST /wxmini/transfer/notify
    │  WxTransferNotifyController → platformTransferService.handleTransferNotify()
    │  → PlatformTransferRecord(ARRIVED/FAILED)
    │  → MerchantSettlementRecord(ARRIVED/FAILED)

=== 超时补偿（每10分钟扫描）===

SettlementTransferTask.processTimeoutTransfers()
    │  → 扫描 TRANSFERRING 超30分钟的记录
    │  → 调用微信查询接口同步状态
```

### request.js 响应解析变更说明

变更前（错误）：
```js
success: (res) => {
  if (res.statusCode === 200) {
    resolve(res.data)  // 返回 { code: 200, msg: "...", data: {...} } 整体
  }
}
```

变更后（正确）：
```js
success: (res) => {
  if (res.statusCode === 200) {
    const responseData = res.data || {}
    if (responseData.code === 200 || responseData.code === 0) {
      resolve(responseData.data !== undefined ? responseData.data : responseData)
    } else if (responseData.code === 401) {
      app.clearLoginInfo()
      reject(new Error('登录已过期'))
    } else {
      reject(new Error(responseData.msg || '请求失败'))
    }
  } else if (res.statusCode === 401) {
    app.clearLoginInfo()
    reject(new Error('登录已过期'))
  }
}
```

### 页面接入模式

所有页面采用 **API优先 + Mock兜底** 模式：
1. 调用后端 API
2. `.then()` 中使用返回数据
3. `.catch()` 中降级到 Mock 数据

这样后端未启动时小程序仍可正常浏览（使用Mock数据），后端就绪后自动切换为真实数据。

## 2026-05-12 前端字段名修复: res.data → res + 模板字段名适配

### 变更概要
- 修复所有商城页面的响应数据解析：`res.data.list` → `res.rows`，`res.data.total` → `res.total`
- 修复 Dashboard 首页字段名适配（`todayAmount` → `todayRevenue` 等）
- 修复商家列表页模板字段名：`products` → `productCount`，`monthlySales` → `totalIncome`

### 问题根因

RuoYi 响应拦截器（`request.js`）返回 `res.data`（即 JSON body），所以页面拿到的 `res` 直接是 `{ code: 200, rows: [...], total: N }`，不需要再 `.data`。

- `TableDataInfo` 返回字段：`rows`（不是 `list`）
- `AjaxResult.success(data)` 返回字段：`data`
- 详情页用 `res.data` 正确（取 AjaxResult 的 data 字段）
- 列表页用 `res.rows` + `res.total`（取 TableDataInfo 的字段）
