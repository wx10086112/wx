# 领域驱动 Maven 多模块重构计划

> 目标：从业务代码全部堆在 ruoyi-system 的单体结构，拆分为按领域自治的 Maven 多模块单体。
> 更新日期：2026-05-18

## 一、当前痛点

- `ruoyi-system` 下 `com.ruoyi.wxmini` 包堆积了 22 个 domain、13 个 mapper、6 个 service
- `MerchantMiniController` 是跨 5 个领域的上帝控制器（16 个端点）
- `DashboardServiceImpl` 注入 4 个不同领域的 mapper
- `IMallOrderService` 已开始膨胀（订单+退款+明细耦合）
- 随着业务增长，单 Service 将膨胀到数千行 if-else

## 二、目标架构

```
ruoyi (parent pom)
├── ruoyi-common            [不变]
├── ruoyi-framework         [不变]
├── ruoyi-quartz            [不变]
├── ruoyi-generator         [不变]
├── ruoyi-system            [清理: 删除所有 com.ruoyi.wxmini 代码]
├── ruoyi-mall-common       [新建: 共享基础设施]
├── ruoyi-mall-user         [新建: 用户域]
├── ruoyi-mall-merchant     [新建: 商家域]
├── ruoyi-mall-product      [新建: 商品域]
├── ruoyi-mall-order        [新建: 订单域]
├── ruoyi-mall-finance      [新建: 财务域]
├── ruoyi-mall-marketing    [新建: 营销域]
├── ruoyi-mall-pay          [新建: 支付域]
├── ruoyi-wxmini            [改造: WeChat 适配层]
└── ruoyi-admin             [增强: DashboardServiceImpl + 依赖所有mall模块]
```

### 每个新模块内部结构（以 mall-order 为例）

```
ruoyi-mall-order/
├── pom.xml
└── src/main/
    ├── java/com/ruoyi/mall/order/
    │   ├── controller/     ← MallOrderController, MallAfterSaleController, MallOrderExtendController
    │   ├── domain/         ← MallOrder, OrderItem, RefundRecord
    │   ├── mapper/         ← MallOrderMapper, OrderItemMapper, RefundRecordMapper
    │   └── service/        ← IMallOrderService + impl/MallOrderServiceImpl
    └── resources/mapper/mall/
        ├── MallOrderMapper.xml
        ├── OrderItemMapper.xml
        └── RefundRecordMapper.xml
```

## 三、模块依赖图

```
ruoyi-common (叶子节点，无内部依赖)
├── ruoyi-system [不变]
├── ruoyi-mall-common
├── ruoyi-quartz / ruoyi-generator
│
├── ruoyi-mall-user        → mall-common
├── ruoyi-mall-merchant    → mall-common
├── ruoyi-mall-product     → mall-common
├── ruoyi-mall-marketing   → mall-common
├── ruoyi-mall-pay         → mall-common
├── ruoyi-mall-order       → mall-common, mall-product
├── ruoyi-mall-finance     → mall-common, mall-order
│
├── ruoyi-framework → ruoyi-admin (依赖所有模块)
└── ruoyi-wxmini → mall-common + 所有domain模块
```

### 依赖规则

- 每个模块可依赖 `ruoyi-mall-common`（始终允许）
- 只允许通过 **Service 接口** 跨模块调用，禁止注入其他模块的 Mapper
- 依赖图保证无环

## 五、关键决策

| 决策 | 方案 | 原因 |
|------|------|------|
| 共享基础设施放哪 | ruoyi-mall-common | JWT/UserContext 每个模块都要用，避免循环依赖 |
| DashboardServiceImpl 放哪 | ruoyi-admin | 注入 4 个 domain 的 mapper，admin 天然有所有依赖 |
| MerchantMiniController | 按领域拆到各模块 | 原来是上帝控制器，拆后各管各的 |
| cross-domain 引用 | 通过 Service 接口而非 Mapper | 只允许 service 层跨模块调用 |
| selectMerchantFlowList | 从 IMerchantService 移到 IFinanceService | TransactionRecord 属于财务域 |
| 包名统一 | com.ruoyi.mall.* | 与原 com.ruoyi.wxmini 区分，语义清晰 |

## 七、配置变更

### 7.1 父 pom.xml

新增 8 个 module 声明 + dependencyManagement 条目

### 7.2 application.yml MyBatis

```yaml
mybatis:
    mapperLocations: classpath*:mapper/**/*Mapper.xml
```

### 7.3 主启动类 ComponentScan

```java
@ComponentScan(basePackages = {"com.ruoyi", "com.ruoyi.mall"})
```

## 八、风险与应对

| 风险 | 应对 |
|------|------|
| MyBatis 扫描新路径失败 | mapperLocations 用 `**` 通配，XML 放 resources/mapper/mall/ |
| @ComponentScan 漏扫新包 | 主启动类添加扫描 com.ruoyi.mall |
| URL 路径变化破坏前端 | 所有 @RequestMapping 保持不变，搬完后 grep 验证 |
| Maven 循环依赖 | 依赖图已保证无环，mvn dependency:tree 验证 |
| @PreAuthorize 权限串 | 权限字符串不变，数据库 sys_menu 不受影响 |
