# 我需要准备的资料

> 这个文件只记录“老板/项目方需要提前准备给开发或配置到服务器里的资料”。  
> 真实密钥不要发到聊天里，不要提交到 Git，后续只给 Xiaomi/服务器配置路径或环境变量名称。

---

## 一、整体业务模式确认

当前项目不是单商家系统，而是 SaaS 多商家系统：

```text
超级管理员
  -> 管理多个分销商
  -> 每个分销商管理多个商家
  -> 每个商家有两个微信小程序
     1. C 端小程序：用户访问、下单、支付
     2. B 端/商家端小程序：商家上架、核销、查看结算
```

支付和结算逻辑：

```text
用户在 C 端小程序微信支付
  -> 钱进入平台微信商户号
  -> 平台记录订单和支付流水
  -> 用户到店/服务完成后，商家端核销
  -> 核销完成后计算平台、商家、分销商收益
  -> 平台生成商家待结算记录
  -> 平台生成分销商待结算记录
  -> 平台调用微信商家转账能力
  -> 微信把钱转给商家/分销商
```

注意：

```text
支付成功不等于马上给商家结算。
只有订单核销完成后，才进入商家/分销商结算。
```

## 二、平台微信支付资料

需要从微信支付商户平台准备：

```text
平台微信商户号 mchId
商户 API 证书序列号 serialNo
商户 API 私钥 apiclient_key.pem
微信支付 APIv3 密钥
微信支付平台证书或平台证书自动下载配置
```

生产环境必须确认：

```text
wx.pay.stub-enabled=false
```

不能让生产环境继续使用模拟支付。

---

## 三、微信支付回调域名

需要准备一个公网 HTTPS 域名。

建议支付回调地址：

```text
https://你的域名/wxmini/pay/notify
```

要求：

```text
必须是 HTTPS
微信服务器能访问
不能用 localhost
不能只用内网 IP
生产环境必须使用正式域名
```

本地联调可以临时使用内网穿透，但上线不能依赖内网穿透。

## 四、每个商家的两个小程序资料

每个商家都要准备两个小程序信息。

### 4.1 C 端小程序

用于用户访问、下单、微信支付。

需要准备：

```text
C 端小程序 AppID
C 端小程序 AppSecret
C 端小程序名称
对应商家 ID
对应分销商 ID，可为空
是否已绑定平台微信商户号
```

必须确认：

```text
C 端小程序 AppID 已经和平台微信商户号完成绑定
否则 JSAPI 支付会失败
```

### 4.2 B 端/商家端小程序

用于商家登录、上架商品、核销订单、查看结算。

需要准备：

```text
B 端小程序 AppID
B 端小程序 AppSecret
B 端小程序名称
对应商家 ID
商家管理员手机号
商家管理员登录账号
```

## 五、微信商家转账资料

本项目选择使用“微信商家转账”完成平台给商家、分销商打款。

需要在微信支付商户平台确认是否已经开通：

```text
商家转账到零钱/银行卡能力
商家转账 API 权限
转账场景报备
转账额度
转账风控要求
转账回调能力
```

建议转账回调地址：

```text
https://你的域名/mall/transfer/wechat/notify
```

需要确认：

```text
微信商家转账使用的平台商户号
转账接口需要的证书、私钥、APIv3 密钥是否与支付共用
转账回调域名是否已配置
转账失败时微信返回的错误码能否完整保存
```

## 六、商家收款资料

每个商家需要准备结算收款信息。

最少需要：

```text
商家 ID
商家名称
结算主体名称
结算联系人姓名
结算联系人手机号
收款方式：微信零钱 / 银行卡 / 微信支付支持的其他方式
收款人 openid 或实名收款标识，按微信商家转账要求确定
银行卡后四位，仅用于后台展示
开户银行名称，仅用于后台展示
结算账户状态：PENDING / VERIFIED / DISABLED
```

如果使用微信零钱转账，需要确认：

```text
收款人微信实名信息
收款人 openid 获取方式
openid 属于哪个小程序或公众号主体
微信商家转账是否要求用户确认收款
```

如果使用银行卡打款，需要确认：

```text
微信商家转账是否支持当前银行卡场景
银行账户实名信息
银行卡号不要明文展示到后台
后台只展示后四位
```

## 八、抽成和结算规则

需要在开发前确认清楚每一类收益规则。

至少要准备：

```text
平台抽成比例
商家结算比例
分销商佣金比例
团购活动是否有单独抽成规则
退款时平台、商家、分销商如何回滚
已到账后退款是否从下次结算抵扣
商家 T+1 结算的具体执行时间
分销商结算周期：T+1 / 每周 / 每月 / 手动审核
```

建议先固定一套默认规则：

```text
用户支付金额
  - 平台佣金
  - 分销商佣金
  = 商家结算金额
```

如果某些商家或团购活动有特殊比例，需要后台支持单独配置。

## 十、服务器配置项

建议让 Xiaomi 按下面结构接入配置，真实值放服务器配置或环境变量。

```yaml
wx:
  pay:
    stub-enabled: false
    mch-id: 平台微信商户号
    mch-serial-no: 商户API证书序列号
    api-v3-key: 微信支付APIv3密钥
    private-key-path: 商户私钥路径
    notify-url: https://你的域名/wxmini/pay/notify
  transfer:
    enabled: true
    notify-url: https://你的域名/mall/transfer/wechat/notify
    scene-id: 微信商家转账场景ID
    remark-prefix: 零点科技团购结算
```

开发环境可以保留：

```yaml
wx:
  pay:
    stub-enabled: true
  transfer:
    enabled: false
```

生产环境必须：

```yaml
wx:
  pay:
    stub-enabled: false
  transfer:
    enabled: true
```

## 十一、联调前检查

真实支付联调前确认：

```text
后端服务可以通过公网 HTTPS 访问
支付回调地址可以被微信访问
平台商户号已开通 JSAPI 支付
C 端小程序 AppID 已绑定平台商户号
订单金额不是 0
订单状态是待支付
支付成功后能写入 payment_record
支付回调验签通过后才修改订单为已支付
```

真实结算联调前确认：

```text
订单必须先核销完成
核销完成后生成 order_profit_ledger
核销完成后生成 merchant_settlement_record
核销完成后生成 distributor_settlement_record
商家/分销商收款资料已通过校验
微信商家转账权限已开通
转账回调地址可以被微信访问
转账成功后能更新为 ARRIVED
转账失败后能更新为 FAILED 并保留失败原因
```

## 十二、不要做的事

```text
不要把 APIv3 密钥发到聊天里
不要把 apiclient_key.pem 提交到 Git
不要在生产环境打开 stub-enabled
不要在创建支付单时直接把订单改为已支付
不要在未收到微信支付回调前生成结算记录
不要在订单未核销前给商家或分销商打款
不要让商家、分销商账号越权查看数据
不要在后台明文展示完整银行卡号
```
