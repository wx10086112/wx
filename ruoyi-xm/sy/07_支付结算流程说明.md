# 07 支付结算流程说明

---

## ⚠️ 审计说明

以下流程中"微信支付"和"微信商家转账"部分为 Stub 实现（详见 `代码审计问题台账.md` P1-2/P1-3/P1-4）：
- 微信支付：返回模拟 prepay_id，无真实统一下单
- 支付回调：无实际 Controller 处理
- 商家转账：只改数据库状态，不真实调微信 API
- 需要配置微信商户号、APIv3 密钥、证书后才能真正跑通

## 支付链路

```
用户确认订单
  → POST /wxmini/order/create → 创建订单（状态=待支付）
  → POST /wxmini/pay/order/create → 获取微信支付参数（Stub ⚠️）
  → wx.requestPayment(payParams) → 调起微信支付
  → 用户输入密码 → 支付成功
  → 微信异步通知后端 /wxmini/pay/notify（未实现 ⚠️）
  → 后端验签 → 更新订单状态 = 已支付
  → 前端轮询或跳转 → 展示核销码
```

## 资金流向

```
用户支付 100 元
  → 进入平台微信商户号（平台统一收款）
  → 核销完成后计算分账
  → 商家应得：85 元
  → 平台抽成：10 元
  → 分销商佣金：5 元
```

## 结算链路

```
核销完成
  → 生成 order_profit_ledger（三方分账流水，状态=WAITING_SETTLEMENT）
  → 生成 merchant_settlement_record（状态=WAITING_T1）
  → T+1 到达 → 运营后台发起打款
  → 调用微信商家转账
  → 微信处理中（状态=TRANSFERRING）
  → 微信回调通知 → 成功（状态=ARRIVED）/ 失败（状态=FAILED）
```

## 三张核心表关系

```
mall_order（订单）
  └→ order_profit_ledger（分账流水，1:1）
      ├→ merchant_settlement_record（商家结算，1:1）
      └→ distributor_settlement_record（分销商结算，1:1）

merchant_settlement_record（商家结算）
  └→ platform_transfer_record（转账记录，N:1）

distributor_settlement_record（分销商结算）
  └→ platform_transfer_record（转账记录，N:1）
```

## 状态机

### 订单状态
```
待支付 → 已支付 → 已核销(已完成) → 结算链路
  ↘ 已取消
  ↘ 退款中 → 已退款
```

### 结算状态
```
WAITING_T1 → TRANSFERRING → ARRIVED
  ↘ CANCELLED          ↘ FAILED
  ↘ REFUND_PROCESSING → REVERSED
```
