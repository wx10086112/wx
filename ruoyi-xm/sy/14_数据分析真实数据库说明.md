> 更新时间：2026-05-29  
> 适用范围：运营后台数据分析页面  
> 对应更新日志：`2026-05-29 待完成：数据分析三页必须改为真实数据库统计`

## 一、改造目标

运营后台下面三个页面必须使用真实数据库统计结果：

```text
商家销售排行：ruoyi-ui/src/views/data-analysis/rank.vue
销售统计：ruoyi-ui/src/views/data-analysis/sales.vue
订单统计：ruoyi-ui/src/views/data-analysis/order-stats.vue
```

禁止继续使用：

```text
1. getMockData()
2. Math.random()
3. setTimeout 模拟数据
4. 接口失败后 fallback 到假数据
5. 前端本地全量过滤、本地排序、本地分页冒充真实统计
```

页面没有数据时，应展示 0、空图表或空表格；接口失败时应展示错误提示。不能生成假销售额、假订单、假排行。

## 二、接口范围

当前前端调用：

```text
GET /mall/dashboard/merchant-rank
GET /mall/dashboard/sales-stats
GET /mall/dashboard/order-stats
```

后端入口：

```text
ruoyi-admin/src/main/java/com/ruoyi/web/controller/mall/MallDashboardExtendController.java
```

实现要求：

```text
1. Controller 只做参数接收和返回，不直接写复杂 SQL 聚合逻辑。
2. 统计逻辑下沉到 DashboardService / DashboardMapper。
3. 后端必须从 mall_order、order_item、merchant、product、product_category、refund_record、write_off_record 等真实业务表统计。
4. 不能写死示例商家、示例分类、随机销售额。
5. 不能接口异常时返回假数据。
```

建议服务方法：

```text
IDashboardService.getMerchantRank(query)
IDashboardService.getSalesStats(query)
IDashboardService.getOrderStats(query)
```

建议 Mapper 方法：

```text
DashboardMapper.selectMerchantRank(query)
DashboardMapper.selectSalesSummary(query)
DashboardMapper.selectCategorySales(query)
DashboardMapper.selectSalesTrend(query)
DashboardMapper.selectOrderSummary(query)
DashboardMapper.selectDailyOrderStats(query)
```

## 三、商家销售排行

数据来源：

```text
merchant
mall_order
order_item
refund_record
```

返回字段：

```text
merchantId
merchantName
salesAmount
orderCount
completedOrderCount
refundAmount
rating
rankNo
```

说明：

```text
salesAmount：已支付/已完成订单的实付金额合计
orderCount：统计范围内订单数
completedOrderCount：统计范围内已完成订单数
refundAmount：统计范围内退款金额
rating：如果当前没有真实评价表，返回 null，不允许随机生成
rankNo：后端按全量排序结果计算，不用当前页 index 代替
```

查询参数：

```text
keyword：商家名称模糊搜索
sortBy：sales / orders / refund / completed
dateRange：today / yesterday / last7days / last30days / month / custom
startDate：自定义开始日期
endDate：自定义结束日期
pageNum：页码
pageSize：每页数量
```

商家销售排行必须后端分页，返回 `TableDataInfo`：

```json
{
  "code": 200,
  "msg": "操作成功",
  "rows": [],
  "total": 0
}
```

## 四、销售统计

数据来源：

```text
mall_order
order_item
product
product_category
refund_record
```

返回字段：

```text
totalSalesAmount
totalOrders
paidOrders
completedOrders
refundAmount
avgOrderAmount
conversionRate
categoryData
trendData
```

说明：

```text
totalSalesAmount：真实支付金额合计
totalOrders：真实订单数
paidOrders：已支付订单数
completedOrders：已完成订单数
refundAmount：退款金额
avgOrderAmount：totalSalesAmount / paidOrders
conversionRate：没有访问/曝光数据时返回 null，不允许固定比例或随机值
categoryData：按商品分类聚合销售额和占比，未分类商品归为“未分类”
trendData：按日期聚合销售额和订单数
```

返回结构：

```json
{
  "code": 200,
  "msg": "操作成功",
  "data": {
    "totalSalesAmount": 0,
    "totalOrders": 0,
    "paidOrders": 0,
    "completedOrders": 0,
    "refundAmount": 0,
    "avgOrderAmount": 0,
    "conversionRate": null,
    "categoryData": [],
    "trendData": []
  }
}
```

## 五、订单统计

数据来源：

```text
mall_order
refund_record
write_off_record
```

返回字段：

```text
totalOrders
paidOrders
completedOrders
refundOrders
abnormalOrders
cancelledOrders
dailyData
```

`dailyData` 结构：

```json
[
  {
    "date": "2026-05-29",
    "newOrders": 0,
    "paidOrders": 0,
    "completed": 0,
    "refund": 0,
    "cancelled": 0,
    "abnormal": 0
  }
]
```

统计要求：

```text
1. dailyData 默认统计最近 30 天。
2. 支持 startDate/endDate 自定义日期范围。
3. 新增订单按 create_time 聚合。
4. 支付订单按 pay_time 或支付状态聚合。
5. 完成订单按 write_off_time 或完成状态聚合。
6. 退款订单按 refund_record 或订单退款状态聚合。
7. 异常订单按当前项目订单状态定义统计。
```

## 六、数据权限

三个接口必须遵守当前 SaaS 数据范围：

```text
超级管理员平台视角：可查看全平台全部商家统计
超级管理员切换分销商视角：只能查看 activeDistributorId 名下商家统计
分销商账号：只能查看自己 distributorId 名下商家统计
商家账号：只能查看自己 merchantId 的统计
```

不能只做前端隐藏，后端接口必须拦截越权统计。

---

## 七、金额单位

金额字段必须统一：

```text
方案 A：后端返回元，使用 BigDecimal/DECIMAL，前端直接保留两位小数。
方案 B：后端返回分，使用 long，字段名建议带 AmountCent，前端统一 /100。
```

禁止同一个页面里同时出现：

```text
一部分字段按元显示
一部分字段按分 /100
一部分字段又由前端随机生成
```
