## P0 — 上线阻塞

### P0-1：后台商家详情无归属校验（越权风险）

- **问题模块**：后台运营管理
- **问题文件**：`ruoyi-mall-merchant/.../controller/MallMerchantController.java` 第 45-48 行
- **当前真实状态**：
  ```java
  @PreAuthorize("@ss.hasPermi('mall:merchant:query')")
  @GetMapping("/{id}")
  public AjaxResult getInfo(@PathVariable Long id) {
      Merchant merchant = merchantService.selectMerchantById(id);  // 直接查，无归属校验
      ...
  }
  ```
- **风险说明**：分销商管理员只要拥有 `mall:merchant:query` 权限，传入任意 `merchantId` 即可查看其他分销商名下的商家详情，包括密钥配置状态
- **建议修复方向**：加 `@DataScopeBiz(merchantAlias = "merchant")` 或在 Service 层校验 `distributorId` 归属
- **是否阻塞上线**：是
- **交给 Xiaomi 的实现要求**：给 `getInfo` 方法添加 `@DataScopeBiz(merchantAlias = "merchant")`，同时在 Service 层 `selectMerchantById` 中追加 `del_flag = '0'` 和 distributorId 过滤条件

### P0-2：后台分销商详情无归属校验（越权风险）

- **问题模块**：后台运营管理
- **问题文件**：`ruoyi-admin/.../controller/mall/MallDistributorController.java` 第 55-58 行
- **当前真实状态**：
  ```java
  @PreAuthorize("@ss.hasPermi('mall:distributor:query')")
  @GetMapping("/{id}")
  public AjaxResult getInfo(@PathVariable Long id) {
      return AjaxResult.success(distributorService.selectDistributorById(id));  // 无归属校验
  }
  ```
- **风险说明**：任意拥有 `mall:distributor:query` 权限的账号可查看任何分销商详情，包括联系人、手机号
- **建议修复方向**：在 Service 层校验当前登录用户的 `distributorId` 与请求 ID 一致（除非是超级管理员）
- **是否阻塞上线**：是
- **交给 Xiaomi 的实现要求**：在 `selectDistributorById` Service 方法中，判断当前用户若非超级管理员，则校验 `id` 是否等于 `SecurityUtils.getDistributorId()`

### P0-3：C端商家列表无 AppID 过滤（数据隔离缺失）

- **问题模块**：C端接口
- **问题文件**：`ruoyi-wxmini/.../controller/WxMerchantController.java` 第 84-101 行
- **当前真实状态**：
  ```java
  @GetMapping("/list")
  public AjaxResult list(...) {
      Merchant query = new Merchant();
      query.setStatus(1);
      List<Merchant> merchants = merchantService.selectMerchantList(query);  // 返回全部状态正常的商家
      ...
  }
  ```
- **风险说明**：C端当前是通过 AppID 决定品牌，但 `/list` 接口返回系统全部商家。如果 AppID 配置错误或未配置，C 端可能展示其他商家的信息
- **建议修复方向**：从 `WxMiniUserContext.getAppIdMerchantId()` 获取当前商家，只返回该商家
- **是否阻塞上线**：是
- **交给 Xiaomi 的实现要求**：在 list 方法中获取 `WxMiniUserContext.getAppIdMerchantId()`，如果非空则只查该 merchantId 对应的商家。如果为空则查全部（兼容演示模式）

### P0-4：Controller 直接注入 Mapper 绕过 Service 层

- **问题模块**：运营后台
- **问题文件**：`MallOrderExtendController.java`（注入 MallOrderMapper），`MallFinanceExtendController.java`（注入 4 个 Mapper）
- **当前真实状态**：Controller 直接调用 Mapper 方法，跳过 Service 层的事务/权限/业务逻辑
- **风险说明**：`approveWithdraw` 审批提现完全在 Controller 中，无事务、无日志、无幂等
- **建议修复方向**：抽取到 Service 实现类
- **是否阻塞上线**：是
- **交给 Xiaomi 的实现要求**：将 `MallFinanceExtendController` 中的提现审批逻辑迁移到 `FinanceServiceImpl`

### P0-5：5 张表物理 DELETE 不可恢复 + 6 张表无 del_flag 列

- **问题模块**：数据库/Mapper
- **问题文件**：`DistributorMapper.xml`、`PlatformIncomeMapper.xml`、`TransactionRecordMapper.xml`、`MallUserMapper.xml`、`UserInfoMapper.xml` 使用 `<delete>`；`WriteOffRecordMapper.xml`、`ProductImageMapper.xml` 无 del_flag

- **是否阻塞上线**：是

### P1-8：运营后台前端路由无权限控制

- **问题模块**：后台前端
- **问题文件**：`ruoyi-ui/src/router/index.js`
- **当前真实状态**：所有业务菜单（商家管理、分销商管理、平台财务、系统管理）定义在 `constantRoutes` 中，**未配置 `permissions` 字段**。只有隐藏路由才用了 `permissions`
- **风险说明**：菜单是否显示完全依赖后端返回的菜单树。如果数据库 `sys_role_menu` 中给 DISTRIBUTOR 角色分配了不该有的菜单，前端会直接显示，用户点击后才被后端 `@PreAuthorize` 拦截
- **建议修复方向**：前端路由也加上 `permissions` 做双保险，低权限用户看到菜单就隐藏
- **是否阻塞上线**：否（后端已做权限，这层是 UI 层面的增强）
