# 06 数据流程说明

> 核心业务数据流转，按流程顺序描述。

---

## ⚠️ 审计说明

以下流程中"支付"和"商家转账"部分为 Stub 实现。
- 流程4（支付）：WxPayController 返回模拟参数，无真实微信支付调用
- 流程6（商家结算）：打款操作只改数据库状态，不调用真实微信转账
- 流程7（分销商结算）：同上
- 详见 `代码审计问题台账.md` P1-2/P1-3/P1-4

## 流程1：商家创建流程

```
运营后台创建商家
  → 写入 merchant 表（状态=待审核）
  → 运营后台审核通过
    → merchant.status = 1（正常）
    → 创建商家端初始员工账号（merchant_user）
```

## 流程2：商品/团购上架流程

```
商家端小程序 → 新增商品
  → 写入 product 表（状态=下架）
  → 商家上架
    → product.status = 1（上架）
    → C端小程序可见
```

## 流程3：用户下单流程

```
C端用户选择商品 → 确认下单
  → 创建 mall_order（状态=待支付）
  → 创建 order_item
  → 返回订单号
```

## 流程4：支付流程

```
用户调起微信支付
  → 钱进入平台微信商户号
  → 微信回调后端
  → 更新 mall_order.status = 已支付
  → 创建 payment_record
  → 生成核销码
```

## 流程5：核销流程

```
用户到店 → 出示核销码
  → 商家扫码/手动输入核销码
  → WriteOffServiceImpl.writeOff()
    → 更新 mall_order.status = 已完成
    → publishEvent(OrderCompletedEvent)
      → SettlementEventListener 异步处理：
        1. 创建 order_profit_ledger（三方分账流水）
        2. 创建 merchant_settlement_record（商家结算记录）
        3. 创建 distributor_settlement_record（分销商结算记录）
```

## 流程6：商家结算流程

```
订单核销完成 → 生成 merchant_settlement_record（状态=WAITING_T1）
  → 到达 T+1 时间
  → 运营后台批量发起打款
    → 调用微信商家转账
    → 状态 = TRANSFERRING
    → 微信回调
      → 成功：状态 = ARRIVED
      → 失败：状态 = FAILED
```

## 流程7：分销商结算流程

```
订单核销完成 → 生成 distributor_settlement_record（状态=WAITING_SETTLEMENT）
  → 每星期一结算上周佣金
  → 运营后台批量发起打款
    → 同商家结算流程
```

## 流程8：退款回滚流程

### 场景1：核销前退款
```
订单状态=已支付 → 退款
  → 状态 = 已退款
  → 无结算记录产生
```

### 场景2：WAITING_T1 退款
```
订单已完成 → 生成结算记录（WAITING_T1）
  → 退款
  → 取消结算记录（状态 = CANCELLED）
```

### 场景3：ARRIVED 后退款
```
订单已完成 → 结算已到账（ARRIVED）
  → 退款
  → 生成负向结算记录
  → 商家余额减少
```

## 流程9：超级管理员切换视角流程

```
超级管理员在分销商管理 → 点击"切换为该分销商视角"
  → 后端设置 LoginUser.activeDistributorId
  → DataScopeBizAspect 根据 activeDistributorId 过滤数据
  → 前端菜单和页面更新为分销商视角
  → 点击"返回平台视角" → 清除 activeDistributorId → 恢复全平台
```
