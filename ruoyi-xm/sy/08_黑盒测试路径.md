# 08 黑盒测试路径

> 端到端黑盒测试清单。  
> 本版重点覆盖：后台商家详情越权、C端/商家端按 AppID 隔离、总后台商家详情可编辑双小程序配置、支付/结算主链路、退款逆向、权限边界。

---

## 一、测试目标

本轮黑盒测试不是只看页面能不能打开，而是要验证以下问题是否真的闭环：

```text
1. 分销商不能越权查看或修改非名下商家详情
2. C端返回数据必须按 c_mini_app_id 归属
3. 商家端返回数据必须按 m_mini_app_id + token 归属
4. 总后台商家详情页能修改 C端/商家端 AppID 与 Secret，并且修改后立即生效
5. 支付、核销、结算、退款链路在权限和数据归属上不穿透
```

---

## 二、测试前置数据

建议至少准备以下测试数据：

```text
平台超管账号：admin

分销商：
- distributorA
- distributorB

商家：
- merchantA，挂在 distributorA 名下
- merchantB，挂在 distributorB 名下

C端小程序配置：
- merchantA.c_mini_app_id = c_appid_A
- merchantB.c_mini_app_id = c_appid_B

商家端小程序配置：
- merchantA.m_mini_app_id = m_appid_A
- merchantB.m_mini_app_id = m_appid_B

商家员工账号：
- staffA，属于 merchantA
- staffB，属于 merchantB

商品：
- merchantA 至少 2 个上架商品
- merchantB 至少 2 个上架商品

订单：
- merchantA 至少 1 个待使用订单、1 个已完成订单、1 个退款订单
- merchantB 至少 1 个待使用订单
```

如果真实微信环境不完整，也至少要准备：

```text
1. 两个不同商家的 AppID 配置
2. 两个不同商家的员工账号
3. 能看出数据差异的商品/订单/门店
```

## 三、黑盒测试清单

## 测试1：超级管理员全平台视角

```text
前置：
- 使用 admin 登录总后台

步骤：
1. 进入商家管理列表
2. 进入订单管理
3. 进入结算管理
4. 进入分销商管理
5. 进入系统管理

预期：
- 可看到全部分销商、全部商家、全部订单、全部结算
- 可看到系统管理入口
- 数据总量明显大于任一单个分销商视角
```

## 测试2：超级管理员切换分销商视角

```text
前置：
- admin 已登录

步骤：
1. 在分销商管理中切换到 distributorA 视角
2. 进入商家管理
3. 进入订单管理
4. 进入结算管理
5. 尝试打开 distributorB 名下商家详情
6. 返回平台视角

预期：
- 切换后只看到 distributorA 名下数据
- 不能查看 distributorB 名下商家详情
- 返回平台视角后恢复查看全部数据
```

## 测试3：分销商登录后台基础隔离

```text
前置：
- 使用 distributorA 后台账号登录

步骤：
1. 进入商家管理列表
2. 进入订单管理
3. 进入结算管理
4. 进入分销商管理
5. 尝试通过接口或页面访问 distributorB 名下商家

预期：
- 只看到 merchantA 及其关联数据
- 看不到 distributorB / merchantB 数据
- 分销商管理入口不可见或无权限
- 强行访问非名下商家应返回 403、无权限或业务拒绝
```

## 测试4：后台商家详情越权

```text
前置：
- distributorA 已登录后台
- 已知 merchantA、merchantB 的 merchantId

步骤：
1. 正常打开 merchantA 的商家详情
2. 手工篡改路由参数或接口参数，把 merchantId 换成 merchantB
3. 尝试查看详情页各个标签：
   - 基本信息
   - 小程序配置
   - 商品/团购
   - 账户管理
   - 结算记录

预期：
- merchantA 可正常打开
- merchantB 必须被拒绝，不能返回详情
- 不能出现“列表页隔离了，但详情接口还能看到”的情况
```

## 测试5：后台商家详情编辑双小程序配置

```text
前置：
- admin 登录后台
- 打开 merchantA 商家详情

步骤：
1. 在商家详情页找到小程序配置区域
2. 修改以下字段并保存：
   - c_mini_app_id
   - c_mini_app_secret
   - m_mini_app_id
   - m_mini_app_secret
3. 保存成功后刷新页面
4. 再次打开 merchantA 详情

预期：
- 页面能回显四个字段
- 点击保存后真实提交成功
- 刷新后能看到最新值
- 不能出现“页面显示能改，但刷新后没落库”的假完成
```

## 测试6：修改 AppID 后 C端数据归属立即生效

```text
前置：
- merchantA 的 c_mini_app_id 已在后台改成新值 c_appid_A_new
- merchantA、merchantB 的商品/门店数据明显不同

步骤：
1. 使用旧的 c_appid_A 请求 C端首页/商家详情
2. 使用新的 c_appid_A_new 请求 C端首页/商家详情
3. 使用 c_appid_B 请求 C端首页/商家详情

预期：
- 旧 appid 若已失效，应返回无商家配置、空数据或明确错误
- 新 appid 返回 merchantA 的数据
- c_appid_B 返回 merchantB 的数据
- 不允许不同 appid 返回同一商家错误数据
```

## 测试7：C端首页按 AppID 返回商家

```text
前置：
- 已准备 c_appid_A 和 c_appid_B

步骤：
1. 用 c_appid_A 打开 C端首页
2. 记录展示的商家名、主门店、商品列表
3. 用 c_appid_B 打开 C端首页
4. 再次记录商家名、主门店、商品列表

预期：
- 两次返回的数据分别属于不同商家
- 页面不再展示“全平台商家列表”
- 数据内容与对应 merchant 配置一致
```

## 测试8：C端商家详情和相册不能跨 AppID 越权

```text
前置：
- 已知 merchantA、merchantB 的 merchantId
- 当前请求头使用 c_appid_A

步骤：
1. 访问 merchantA 商家详情
2. 访问 merchantA 相册接口
3. 手工把路径 merchantId 改成 merchantB
4. 再次访问详情和相册

预期：
- merchantA 正常返回
- merchantB 必须被拒绝，或返回空数据
- 不能因为前端传了 merchantId 就切到其他商家
```

## 测试9：C端登录归属校验

```text
前置：
- 已配置 merchantA 的 c_mini_app_id / secret

步骤：
1. 用 c_appid_A 发起 C端登录
2. 登录后进入“我的订单”
3. 检查订单是否只属于 merchantA
4. 切换到 c_appid_B 再次登录

预期：
- 登录返回的 token 归属于当前 AppID 对应商家
- 登录后只能看到当前商家的订单与用户态数据
- 不能跨 AppID 查看其他商家订单
```

## 测试10：商家端登录与 AppID 一致性

```text
前置：
- staffA 属于 merchantA
- merchantA.m_mini_app_id = m_appid_A
- merchantB.m_mini_app_id = m_appid_B

步骤：
1. 用 staffA + m_appid_A 登录商家端
2. 用 staffA + m_appid_B 登录商家端
3. 用 staffB + m_appid_B 登录商家端

预期：
- staffA + m_appid_A：登录成功
- staffA + m_appid_B：必须失败，返回 403 或业务错误
- staffB + m_appid_B：登录成功
```

```text
4. 打开门店信息

```

## 测试12：商家端 token 与 AppID 不匹配

```text
前置：
- 已拿到 staffA 的有效 token

步骤：
1. 请求头带 staffA token + X-Merchant-AppId = m_appid_A 访问订单列表
2. 请求头改为 staffA token + X-Merchant-AppId = m_appid_B 再访问订单列表
3. 请求头只带 X-Merchant-AppId，不带 token 访问订单列表

预期：
- token + 正确 AppID：200
- token + 错误 AppID：403
- 无 token 只有 AppID：401
```

## 测试13：商家端新增/编辑不能信任前端 merchantId


## 四、重点黑盒结论判定

如果出现以下任一情况，本轮黑盒测试直接判定不通过：

```text
1. 分销商还能通过 merchantId 查看其他分销商名下商家详情
2. C端不同 AppID 返回同一个商家数据，或能跨 AppID 查看其他商家数据
3. 商家端只凭 AppID 无 token 还能访问业务接口
4. token 与 X-Merchant-AppId 不一致时仍能访问成功
5. 总后台商家详情页不能真正修改并保存 c/m 两套 AppID/Secret
6. 修改 AppID 后，后端数据归属没有按新配置切换
7. 支付或结算链路出现跨商家串数据
```

# 2026-05-29 最新补充：数据分析黑盒测试

## 测试目标

验证后台数据分析三页不是 mock，而是真实数据库统计：

```text

5. merchantB 至少 2 笔订单：已支付、已完成各 1 笔。
```
