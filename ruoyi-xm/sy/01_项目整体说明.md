# 01 项目整体说明

## 系统定位

本地生活团购商城，类似美团/大众点评的到店团购模式。消费者在 C 端小程序购买团购套餐，到店后由商家扫码或手动核销完成消费。

## 技术栈

| 层级 | 技术 |
|------|------|
| 后端框架 | Spring Boot 2.5.15 + MyBatis + RuoYi v3.8.9 |
| Java 版本 | Java 8 |
| 构建工具 | Maven 多模块 |
| 数据库 | MySQL 8 |
| 缓存 | Redis |
| 微信 SDK | WxJava 4.7.0 |
| 后台前端 | Vue 2.6 + Element UI 2.15 |
| C 端小程序 | 原生微信小程序 |
| 商家端小程序 | 原生微信小程序 |

## 四端架构

```
┌──────────────┐  ┌──────────────┐  ┌──────────────┐  ┌──────────────┐
│  C 端小程序   │  │ 商家端小程序  │  │  运营后台     │  │  后端服务     │
│  (wx_app)    │  │(merchant_app)│  │ (ruoyi-ui)   │  │(ruoyi-admin) │
│  消费者使用   │  │ 商家/店员使用 │  │ 平台运营使用 │  │ 提供所有API  │
└──────┬───────┘  └──────┬───────┘  └──────┬───────┘  └──────┬───────┘
       └─────────────────┴─────────────────┴─────────────────┘
                    HTTP REST API (localhost:8080)
```

## 多商家双小程序模型

每个商家有两套独立微信小程序：
- **C 端小程序**：消费者浏览、下单、支付（配置于 `merchant.c_mini_app_id`）
- **商家端小程序**：商家上架、核销、结算（配置于 `merchant.m_mini_app_id`）

后端通过 AppID 识别商家，`merchantId` 做数据隔离。
