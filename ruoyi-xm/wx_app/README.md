# `wx_app` 微信小程序说明

## 项目定位

`wx_app` 是本地生活/到店服务场景的微信小程序前端，围绕“用户下单购买 + 到店核销 + 商家后台管理”构建完整业务闭环。

这一套小程序前端实际包含两部分：

- C 端用户小程序：首页浏览、商品详情、下单支付、订单管理、个人中心
- 商家 B 端小程序：商家登录、工作台、订单核销、商品管理、员工权限、门店配置、财务与营销模块

适合在简历中定义为：

> 独立负责/深度参与微信小程序前端开发，完成本地生活团购场景下 C 端用户购买链路与商家 B 端核销管理链路建设。

---

## 核心业务能力

### 1. C 端用户小程序

用户侧围绕“发现门店 - 浏览商品 - 下单支付 - 到店使用”展开，主要能力包括：

- 首页聚合门店与团购商品，支持定位授权、距离展示、门店快捷联系与地图导航
- 商品详情页展示套餐内容、使用规则、有效期、预约与退款说明
- 下单页支持商品确认、价格计算、手机号提交、订单创建
- 订单中心支持按状态筛选待支付、待使用、退款/售后订单
- 订单详情支持支付、取消订单、退款售后、再次购买等操作
- 个人中心支持微信登录、手机号绑定、个人资料维护、联系客服

### 2. 商家 B 端小程序

商家侧围绕“登录后台 - 处理订单 - 核销服务 - 管理门店”展开，主要能力包括：

- 基于商家入口和账号密码登录商家后台
- 工作台集中展示待核销、已完成、退款中、在售套餐等经营数据
- 支持订单管理、核销记录查询、商品上下架、商品编辑
- 支持门店信息维护、营业状态切换、员工与权限管理
- 支持财务结算、营销活动等商家运营能力接入

### 3. 闭环场景

项目不是单页展示型小程序，而是完整的业务闭环：

1. 用户登录小程序
2. 浏览门店与团购商品
3. 创建订单并发起支付
4. 生成订单核销码/二维码
5. 商家侧扫码或人工核销
6. 订单状态流转为已完成，形成到店服务闭环

## 技术实现亮点

### 原生微信小程序分层实现

项目基于原生微信小程序开发，使用 `glass-easel` 组件框架，按职责拆分为：

- `pages/`：页面层，区分用户端页面与商家端页面
- `components/`：通用组件，如订单卡片、商品卡片、二维码组件、空状态组件
- `api/`：接口层，拆分 C 端接口与商家端接口
- `services/`：业务配置与模板服务
- `utils/`：请求封装、状态流转、格式化工具、商家端工具方法

这套结构使页面逻辑、接口调用和业务工具解耦，便于后续迭代与维护。

### 双端鉴权与请求封装

项目针对不同业务身份分别封装了请求层：

- 用户端使用 `utils/request.js`
- 商家端使用 `utils/merchant-request.js`

实现点包括：

- 动态读取运行环境 `baseUrl`
- 自动注入小程序 `AppId`
- 用户端与商家端分别维护独立 token
- 按身份附带不同请求头，隔离 C 端与 B 端接口
- 对登录失效、业务失败、网络异常做统一拦截与提示

### 模板化配置能力

通过 `services/template/` 实现模板配置合并机制：

- 内置默认模板配置
- 支持远程接口下发品牌配置
- 支持本地 mock 配置兜底
- 通过深度合并实现“页面结构固定、品牌内容可配置”

这让首页文案、品牌信息、功能开关、页面文案可以按商家或项目快速调整，减少硬编码。

### 订单状态与本地兜底机制

项目对订单流转做了统一封装，支持：

- 待支付
- 待使用
- 已完成
- 退款中
- 已退款
- 已取消
- 已关闭

同时保留了本地 `storage` 兜底逻辑：

- 后端未完全联通时，仍可基于本地数据演示核心链路
- 支持本地订单缓存、筛选状态缓存、模拟状态流转
- 方便联调期开发、自测和演示环境快速验证

### 核销二维码能力

项目内置二维码组件 `components/qrcode/`，用于展示订单核销码：

- 前端直接在 Canvas 绘制二维码
- 用户端订单页、订单详情页可直接展示核销码
- 商家端可结合扫码能力完成核销场景落地

这部分是“购买后到店使用”场景里的关键交付点，也是项目业务闭环的重要体现。

### 商家角色与权限控制

商家端实现了基础 RBAC 权限思路，区分如 `owner`、`member` 等角色，并按权限码控制：

- 订单管理
- 扫码核销
- 手动核销
- 核销记录
- 商品管理
- 门店管理
- 员工管理
- 财务管理
- 营销管理

前端在页面入口、快捷操作和关键动作上都做了权限校验，避免低权限账号越权操作。

## 小程序端负责内容总结

从代码职责上看，`wx_app` 主要完成了以下前端工作：

- 小程序全局初始化、运行环境配置、登录态恢复
- 微信登录、手机号绑定、用户资料维护
- 门店列表、商品列表、详情展示与交互
- 下单、支付调起、订单状态展示
- 核销码生成与订单使用链路承接
- 商家登录、工作台、订单/商品/门店/员工后台页面开发
- 商家角色权限控制与多模块入口组织
- API 对接层抽象、模板配置抽象、工具方法沉淀
