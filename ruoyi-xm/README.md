# SaaS 多端商家系统项目说明

## 项目定位

本项目是一套面向本地生活与到店团购场景的 SaaS 多端商家系统，包含：

- 消费者使用的 C 端小程序
- 商家/店员使用的商家端小程序能力
- 平台运营后台 Web
- 统一后端与微信能力接入层

当前代码结构已经调整为“前端小程序单仓整合”模式：

- `wx_app` 同时承载 C 端页面和商家端页面
- 原独立目录 `merchant_app` 已废弃并移除
- 商家端页面现位于 `wx_app/pages/merchant/*`
- 商家端接口封装现位于 `wx_app/api/merchant-mini/*`

这次调整解决的是目录重复维护问题，不改变业务边界。消费者与商家仍然是两套登录态、两套路由入口、两套接口前缀。

## 顶层目录说明

| 目录/文件 | 说明 |
|-----------|------|
| `wx_app/` | 小程序前端主目录，同时包含 C 端页面和商家端页面。C 端页面位于 `pages/*`，商家端页面位于 `pages/merchant/*`。 |
| `ruoyi-vue-wxmini-main/` | 后端与运营后台主工程，基于 RuoYi-Vue 3.8.9 + Spring Boot + Maven 多模块。 |
| `merchant_images/` | 本地商家图片存储目录，按商家 ID 和图片类型组织头像、门店图、Banner、商品图等资源。 |
| `项目完整文档.md` | 当前代码口径下的端到端总览文档。 |
| `目录说明.md` | 目录职责与后续维护边界说明。 |
| `PROGRESS.md` | 当前开发进度与联调状态。 |
| `更新日志.md` | 历史变更记录。 |

## 小程序前端结构

### `wx_app` 中的 C 端

主要页面：

- 首页、搜索、搜索结果
- 商家/门店详情
- 商品/套餐详情
- 购物车、结算页
- 订单列表、订单详情
- 优惠券、收藏、联系、资料编辑、评价

主要特点：

- 以 C 端交易闭环为主线
- 已接入模板配置读取和统一请求封装
- 仍有部分页面保留 mock 或本地降级逻辑

### `wx_app` 中的商家端

主要页面位于 `pages/merchant/*`：

- 登录、工作台
- 订单、订单详情
- 核销、核销记录
- 商品、商品编辑
- 门店、员工、财务、营销、入驻申请、我的

主要配套能力：

- 商家端请求封装：`utils/merchant-request.js`
- 商家端工具函数：`utils/merchant-util.js`
- 商家端接口模块：`api/merchant-mini/*`
- 商家端独立登录态：`merchantToken`、`isMerchantLoggedIn`

## 运营后台与后端

后端主工程位于 `ruoyi-vue-wxmini-main/`。

| 模块 | 职责 |
|------|------|
| `ruoyi-admin` | Spring Boot 启动入口，提供运营后台 API 和商城扩展接口。 |
| `ruoyi-ui` | 运营后台前端，基于 Vue 2 + Element UI。 |
| `ruoyi-common` | 若依公共工具与基础组件。 |
| `ruoyi-framework` | 安全框架、过滤器、权限与 Web 配置。 |
| `ruoyi-system` | 若依系统管理模块。 |
| `ruoyi-quartz` | 定时任务模块。 |
| `ruoyi-generator` | 代码生成模块。 |
| `ruoyi-wxmini` | 微信小程序接入层，承载 C 端与商家端入口接口。 |
| `ruoyi-mall-common` | 商城公共能力，包含 JWT 上下文、支付抽象与通用 BO/VO。 |
| `ruoyi-mall-user` | C 端用户域。 |
| `ruoyi-mall-merchant` | 商家、门店、商家员工与审核域。 |
| `ruoyi-mall-product` | 商品、分类、团购活动域。 |
| `ruoyi-mall-order` | 订单、订单项、退款/售后域。 |
| `ruoyi-mall-finance` | 流水、分账、提现、报表域。 |
| `ruoyi-mall-marketing` | Banner、优惠券等营销域。 |
| `ruoyi-mall-pay` | 微信支付、支付记录、回调处理域。 |

## 当前维护口径

后续文档与代码都按下面这套口径维护：

1. 不再把 `merchant_app/` 当作现行代码目录。
2. 所有商家端前端说明，统一落到 `wx_app/pages/merchant/*`、`wx_app/api/merchant-mini/*`、`wx_app/utils/merchant-*`。
3. 如果历史复盘文档提到 `merchant_app`，默认视为“旧目录名称”，不是当前主线目录。

## 当前重点问题

- C 端与商家端前端虽已合仓，但仍有部分接口处于 mock/占位状态。
- 微信支付、退款、分账、结算闭环仍需继续打通。
- 运营后台业务页面仍存在 mock 与真实 API 混用。
- 多租户隔离、商家权限、门店权限与模板归属仍需继续固化。

## 建议推进顺序

1. 统一数据模型：商家、门店、员工、用户、商品、订单、支付、退款、优惠券、模板配置。
2. 打通 C 端真实交易闭环：登录、商品、下单、支付、订单、退款、评价。
3. 打通商家端真实履约闭环：登录、订单处理、核销、商品管理、门店维护、财务查看。
4. 打通平台后台闭环：商家审核、订单监管、售后、提现审批、财务报表、数据分析。
5. 完善 SaaS 能力：租户隔离、角色权限、多门店、模板配置、定时任务、消息通知。
