# SaaS 多端商家系统项目说明

## 项目定位

本项目目标是建设一套完整的 **SaaS 多端商家系统**，面向本地生活、到店团购、门店服务、核销履约、商家经营和平台运营场景。

系统不是单一小程序模板，也不是只做后台管理页面，而是由多端协同组成：

- C 端微信小程序：消费者浏览、下单、支付、核销、评价。
- 商家端微信小程序：商家/店员处理订单、扫码核销、管理商品、维护门店、查看财务。
- 运营后台 Web：平台运营管理商家、商品、订单、售后、财务、数据和系统权限。
- 后端服务：统一承载用户、商家、商品、订单、支付、营销、财务、鉴权和微信能力。

当前代码已经具备上述多端雏形，后续应按 SaaS 化、多商家、多门店、多角色、多租户隔离的方向继续演进。

## 顶层目录说明

| 目录/文件 | 说明 |
|-----------|------|
| `wx_app/` | C 端原生微信小程序，面向消费者，负责浏览商品、购物车、下单、支付、订单、核销码、收藏、优惠券等前台交易闭环。 |
| `merchant_app/` | 商家端原生微信小程序，面向商家/店员，负责工作台、订单处理、扫码核销、商品管理、门店设置、员工权限、财务收益、营销和入驻申请。 |
| `ruoyi-vue-wxmini-main/` | 后端与运营后台主工程，基于 RuoYi-Vue 3.8.9 + Spring Boot + Maven 多模块，包含 `ruoyi-ui` 运营后台和多个 `ruoyi-mall-*` 领域模块。 |
| `merchant_images/` | 本地商家图片存储目录，按商家 ID 和图片类型组织头像、门店图、Banner、商品图等资源。 |
| `项目完整文档.md` | 端到端项目总览文档，记录系统架构、端侧功能、接口、数据库、流程和当前状态。 |
| `更新日志.md` | 顶层项目变更记录。 |

## 当前端侧范围

### C 端小程序 `wx_app`

主要页面：

- 首页、购物车、我的
- 搜索、搜索结果
- 商家/门店详情
- 商品/套餐详情
- 结算页
- 订单列表、订单详情
- 优惠券、收藏、客服、个人资料、评价

当前特点：

- 已实现 API 优先 + 本地 mock 降级。
- 已接入统一模板配置读取逻辑。
- 支持购物车、本地下单、模拟支付和核销二维码展示。
- 后续重点是接入真实登录、真实支付、订单状态回调、优惠券、评价、收藏和多租户模板配置。

### 商家端小程序 `merchant_app`

主要页面：

- 登录、工作台、订单、订单详情
- 核销、核销记录
- 商品、商品编辑
- 门店设置、员工管理
- 财务收益、营销活动、我的、入驻申请

当前特点：

- 已具备商家端完整页面骨架。
- 已定义商家端独立 token、权限码和 API 前缀。
- 核销链路与 C 端核销码模型已对齐。
- 后续重点是补齐真实员工管理、营销活动、入驻审核、退款审核、财务提现和多门店权限。

### 运营后台 `ruoyi-vue-wxmini-main/ruoyi-ui`

主要范围：

- 平台工作台
- 商家管理、入驻审核、商家提现
- 订单管理、售后订单、异常订单
- 平台流水、商家分账、提现记录、财务报表、收益统计
- 数据分析
- 系统权限和日志

当前特点：

- 基于 Vue 2 + Element UI。
- 保留若依系统管理能力。
- 商城业务页面部分使用 mock，部分预留真实 API。
- 后续重点是将商品、营销、数据中心等已创建页面接入路由和真实后端。

| 模块 | 职责 |

| `ruoyi-mall-merchant` | 商家域：商家主体、门店、商家员工、审核。 |

| `ruoyi-mall-order` | 订单域：订单、订单项、退款/售后、订单统计。 |
| `ruoyi-mall-finance` | 财务域：流水、分账、提现、报表。 |
| `ruoyi-mall-marketing` | 营销域：Banner、优惠券，目前以领域实体为主，待补齐业务层。 |
| `ruoyi-mall-pay` | 支付域：支付记录、微信支付下单、查询、回调，目前核心逻辑仍需完善。 |

## SaaS 化核心边界

后续开发应始终遵守以下边界：

- 平台运营方管理所有商家、门店、商品、订单、财务、模板和审核。
- 商家只能管理自己名下的门店、商品、订单、员工、营销和财务。
- 店员只能在权限范围内处理订单、核销和查看必要数据。
- C 端用户只能看到当前小程序或当前商家上下文中的品牌、门店、商品和订单。
- 所有业务数据必须具备 `merchantId`，多门店数据还应具备 `storeId`。
- 鉴权上下文应能明确区分平台用户、C 端用户、商家员工和所属商家/门店。

## 当前重点问题

- 顶层历史文档曾将项目描述为“只做 C 端模板”，已经与当前代码范围不一致。
- C 端 `app.json` 当前主 Tab 是首页/购物车/我的，部分旧文档仍写首页/订单/我的。
- 营销、支付、部分商家端操作接口仍处于待实现或 TODO 状态。
- 运营后台业务页面仍有 mock 与真实 API 混用，需要统一切换策略。
- 多租户隔离、模板配置归属、商家端员工权限与平台后台权限需要继续固化。

## 建议推进顺序

1. 统一数据模型：商家、门店、员工、用户、商品、订单、支付、退款、优惠券、模板配置。
2. 打通 C 端交易闭环：登录、商品、下单、支付、订单、核销、退款、评价。
3. 打通商家端履约闭环：登录、订单处理、扫码核销、核销记录、商品上下架、门店维护。
4. 打通平台后台闭环：商家审核、商品/订单监管、售后、提现审批、财务报表、数据分析。
5. 完善 SaaS 能力：租户隔离、角色权限、模板配置、多门店、操作审计、定时任务、消息通知。
